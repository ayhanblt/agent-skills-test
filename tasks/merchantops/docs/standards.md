# Pinned public technical notes

- tus 1.0.0 Core + Creation + Checksum: https://tus.io/protocols/resumable-upload — OPTIONS advertises versions/extensions, POST creates a resource, HEAD returns its authoritative offset, and PATCH commits only when the supplied offset equals the resource's current offset. Except OPTIONS, carry Tus-Resumable; unsupported/missing version is 412 with Tus-Version. Invalid PATCH media type is 415, offset mismatch is 409, success is 204. HEAD uses Cache-Control: no-store. The Checksum extension sends two tokens, algorithm and base64 digest. Unknown algorithm or malformed header is 400, mismatch is 460 without progress. This study declares its supported subset in each task.
- HTTP Semantics RFC 9110 §§8.8.3 and 13.1.1: https://www.ietf.org/rfc/rfc9110.html#section-13.1.1 — strong ETag comparison for If-Match. A weak tag never strongly matches; a valid list succeeds when a strong member matches. This study's endpoint requires a specific observed revision and explicitly excludes wildcard writes.
- TanStack Query React 5.90.21: https://tanstack.com/query/v5/docs/framework/react/guides/optimistic-updates — cancel outstanding queries before applying speculative patches; context from onMutate can be read in onError/onSettled. Multiple independent mutations may settle out of order; reconstruct view from server data and remaining operations. useMutationState can select pending variables by mutation key. For conditional writes, preserve the tag of the version the user actually edited.
- SQLite: https://sqlite.org/atomiccommit.html — transaction failure rolls back all contained writes. SQLite serializes writers; reads and writes in persisted state transitions must use the same transaction. BLOBs, counters, and cents here use integer/byte operations.
