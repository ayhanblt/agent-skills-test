Export createPayments(provider,store). store is a shared Map surviving service re-creation. Return {pay(key,request), webhook(event), status(key)}. The request contains {amount,currency}. Reject empty keys, non-positive or non-integer amounts, and currencies other than three uppercase letters with code INVALID before any provider call. Reusing a key with a different amount or currency rejects with code CONFLICT. Concurrent identical requests share a single provider call. Completed identical requests replay the existing result. Unrelated keys progress independently. provider.charge(key,request) can reject with code TIMEOUT after charging; then return {state:'pending'} and keep the original request/key. A repeated pay while pending calls provider.lookup(key), never charge again; lookup returns {state,version,receipt?}. provider.charge normally returns that shape. webhook({key,state,version,receipt?}) is synchronous and returns current status. Throw with code UNKNOWN for unknown keys, or INVALID for invalid state values or versions that are not nonnegative integers. status returns the latest snapshot or null. Apply strictly increasing integer nonnegative versions only. States pending,succeeded,failed; terminal status cannot regress to pending or switch terminal outcome, even with higher version. Ignore duplicate/older events. Return defensive snapshots. Concurrent retries coalesce. Transport failures other than TIMEOUT reject without erasing identity; a later pay uses lookup. No network, secrets, database or dependencies.

### Coordinating multiple service instances
Two live services using the same Map must share the in-flight charge or lookup for the same key. A second service joining an unresolved charge must wait for its result without starting a lookup. After that charge times out, all concurrent retries across services share a single lookup. A conflicting request still rejects immediately. Services with different stores must remain independent.

If a webhook commits a terminal snapshot while a lookup is pending, an older, pending, or contradictory lookup result cannot overwrite that snapshot. If that lookup subsequently throws, all waiting pay calls return the committed terminal snapshot. If it throws while the record is still pending, propagate the error and allow a later lookup. A newer event that confirms the same terminal state but omits receipt preserves the existing receipt. A newer event with a receipt may replace it. Do not regress the committed version on ignored events.

Public snapshots from pay, webhook and status contain only state, version when known, and receipt when known. Neither the idempotency key nor shared in-flight bookkeeping belongs in the result.
