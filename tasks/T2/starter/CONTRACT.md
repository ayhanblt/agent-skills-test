Export createPayments(provider,store). store is a shared Map surviving service re-creation. Return {pay(key,request), webhook(event), status(key)}. Same validation/conflict semantics as T1. provider.charge(key,request) can reject with code TIMEOUT after charging; then return {state:'pending'} and keep the original request/key. A repeated pay while pending calls provider.lookup(key), never charge again; lookup returns {state,version,receipt?}. provider.charge normally returns that shape. webhook({key,state,version,receipt?}) returns current status; unknown keys reject UNKNOWN. status returns the latest snapshot or null. Apply strictly increasing integer nonnegative versions only. States pending,succeeded,failed; terminal status cannot regress to pending or switch terminal outcome, even with higher version. Ignore duplicate/older events. Return defensive snapshots. Concurrent retries coalesce. Transport failures other than TIMEOUT reject without erasing identity; a later pay uses lookup. No network, secrets, database or dependencies.
