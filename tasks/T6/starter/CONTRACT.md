Export createTransfer(storage,{size,sha256},afterCommit=()=>{}). storage adapter: read() returns Buffer of committed bytes (initially empty); commit(buffer) atomically durably replaces bytes and may throw; no direct filesystem/network. Return {offset(),write(offset,bytes,chunkSha256),finish()}; synchronous methods. Validate declared size is nonnegative integer and sha256 is 64 lowercase hex. write validates nonnegative integer offset, nonempty Buffer, matching SHA-256, no gap, no overflow. Invalid operations throw code INVALID and leave bytes unchanged. New chunk must start exactly at committed offset. A fully committed identical replay (also subrange) returns the current offset. A replay with a conflicting overlap rejects INVALID. Matching partial overlap is accepted as described in Recovery with different chunk boundaries. Return durable offset only after commit succeeds; propagate storage errors. Recreating the transfer resumes from storage.read(), rejecting persisted length > size. finish returns a defensive Buffer iff exact length and whole hash agree, otherwise throws INVALID. Never reset storage on failure. For crash recovery, storage.read() gives durable bytes; commit(buffer) atomically writes and may throw BEFORE commit. afterCommit() runs after every NEW successful commit, before ACK (write return), and may throw a simulated crash AFTER disk commit. Recreate instance after crash; identical retransmission must ACK durable offset without another commit or afterCommit call. Do not store offset only in memory, truncate bytes, duplicate data or mask commit/crash errors. Multiple instances may interleave synchronous calls against the same adapter; read current committed state for each operation. finish verifies bytes from storage now, not a cached offset/hash. No new dependencies, external stores or changes to storage adapter.

### Recovery with different chunk boundaries
A retransmission may start inside committed bytes and extend beyond the current offset, for example if the sender changed chunk sizes after a lost ACK. Compare the entire overlapping prefix byte-for-byte with current durable bytes. On mismatch throw INVALID without any commit or callback. On a match, commit only the new suffix in one atomic update. The digest still covers the entire incoming chunk, including the overlapping bytes. A fully committed matching replay remains a no-op.

A failed commit leaves the old offset valid for retry. If the commit succeeds but afterCommit throws, the newly appended suffix is already durable and replay must not commit again. A callback may synchronously call a second transfer on the same adapter. ACK the latest durable offset after the callback returns, including any progress by the second transfer. If the callback throws, propagate it, preserving all committed bytes.
