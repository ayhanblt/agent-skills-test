# T3 — Optimistic refunds
Extend RefundPanel using the installed TanStack Query v5. Keep the endpoint and accessible labels. Immediately reflect every submitted valid amount in both payment detail and list while it is pending. A failure removes only that request's optimistic amount; keep other pending or confirmed requests. Surface a visible error and offer a deliberate retry, with no automatic retry of a monetary operation. Do not resubmit successes, including after unmount/remount.
A POST returns a complete payment whose refunded total is authoritative and monotonic. Out-of-order mutation responses and stale reads must not overwrite a higher acknowledged total. Reconcile both caches with the server after concurrent work settles. Treat AbortSignal only as a delivery hint; an old GET may resolve after an optimistic mutation begins. User may submit another request while an earlier one is pending. No changes to server behavior or dependencies.
